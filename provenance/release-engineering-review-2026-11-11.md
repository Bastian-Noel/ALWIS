# Publication engineering review — 11 November 2026

This records technical review and the maintainer decision; it is not a third-party permission or a formal legal opinion.

- Native source correspondence: successful native Actions 42924952591 and main Studio 42930786466. The QA manifest pins all native input hashes, WASM/glue and the seven upstream archives with Emscripten runtime sources. Publication now checks the shipped WASM against that manifest and attaches the exact corresponding-source bundle and receipts to the release. Local WSL linker replay of the same source inputs identifies PHP, embedded MariaDB and Emscripten runtime archives; its local binary hash is not presented as the CI hash.
- Editor boundary: original editor adapters are MIT under the owner's explicit grant. TypeScript and SWC retain Apache-2.0 notices in independent editor workers/assets. verify-editor-boundary.py passes; they are not native link inputs. This is the engineering basis for treating the editor tools separately from the GPL native runtime.
- Source reuse: owner authorship declaration, recorded source study map and automated comparison found no identified unlicensed copy in the screened inputs. This is not proof of originality; future findings must reopen review. No blanket ownership is asserted over third-party code.
- Release notices and functionality: native parity, cURL, fatal recovery, repeated database requests, multiple guest sessions, persistence/restart and full main Studio validation have succeeded. Exact upstream notices, PHP/Zend later-version elections, wolfSSL MariaDB exception and toolchain notices remain packaged. The broad previous release-notice finding is replaced by artifact-specific checks, not a claim that tests establish legal rights.

The known PHP formatter incompatibility remains an open finding. The owner explicitly instructed its exclusion from the publication gate for 2026.11.0-beta.1. publication_policy.py allows only that finding and the two named files, checks the preserved notice and version, and rejects any additional blocker. Future versions require a new decision or a compatible replacement. The old `developmentBuildException` remains historical; the explicit `publicationException` controls this release.
