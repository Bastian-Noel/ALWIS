# ALWIS 2026.11.0 Beta 3

Cette correction améliore les interactions du studio après la bêta 2.

- L’ouverture de l’aperçu dans une fenêtre utilise le trajet HTTP de l’invité ou de l’hôte, sans accéder à un moteur local absent. Un échec ferme la fenêtre provisoire et explique le problème.
- Le chargement simultané des ressources de plusieurs aperçus invités utilise une file bornée (32 attentes, 16 Mio de corps en attente), avec au plus trois opérations HTTP/cookies actives par invité. Les demandes en attente expirent au plus tard après 10 secondes, avant le délai du relais d’aperçu et sont annulées à la déconnexion ; aucun POST n’est rejoué.
- Le panneau Réseau montre les dernières requêtes en premier et garde la sélection par identifiant.
- Les tables du schéma peuvent être déplacées dans les quatre directions, y compris vers des coordonnées négatives. Maintenir le déplacement près d’un bord fait défiler la vue. Les positions sont partagées en direct, transmises aux nouveaux invités et conservées à l’enregistrement. Le panoramique et le zoom restent propres à chacun, sauf suivi explicite.
- Les avatars de présence apparaissent sur le dossier replié contenant le fichier ouvert par un autre participant, puis reviennent au fichier quand ce dossier est déplié.
- Le bouton Enregistrer devient indisponible pendant la sauvegarde, avec un indicateur et le texte « Enregistrement… ». L’état reste lisible lorsque les animations sont réduites.

Les nouveaux tests couvrent un hôte, deux invités, les fenêtres réelles, les déplacements avant relâchement de la souris, l’arrivée tardive, les dossiers repliés, l’enregistrement et la réouverture dans Chromium et Firefox. Les contrôles existants du schéma et de l’aperçu restent appliqués.

Le moteur natif est inchangé. L’exception interne documentée sur les deux fichiers historiques de formatage PHP est reconduite pour cette version ; leurs notices et le constat de compatibilité non résolu sont conservés. [État de publication](../../provenance/release-licensing-status.json).
